# Modal layer

## 1. Purpose and scope

Noble's Keep shows no free-standing UI. Its owner's rule is that "any UI will
be limited to modals, and only if invoked via icons on the screen, such as
interlocking gears on the bottom row opening the settings." The game draws its
own diegetic tabletop (books, tool tiles, the gear icon) directly with
`libmsdf`; libcontrols is used only for the controls *inside* a modal: the
settings and pause modals, and possibly the contents of an opened book such as
a ledger page.

libcontrols 0.2.0 has no modal support. The only layering it has is
`DrawControl::draw_overlay`, a second draw pass `ControlHost` makes after every
control's `draw`, used by `Button`, `Options` and `Radio` for tooltips. It has
no notion of a layer that takes all input, no transitions and no dismissal.

This plan adds:

- `ModalState`: an app-owned, `Arc`-shared state machine that persists across
  host rebuilds. It knows which modal is open, its phase and transition
  progress, carries the modal's focus and drag between rebuilds, and queues
  `ModalEvent`s.
- `Modal<'a>`: built each time the host is built, like `Panel`. It holds the
  content controls, the frame and content rects, the app's frame painter
  (`ModalFrame`), the backdrop and the dismiss rules.
- A modal layer in `ControlHost`: while a modal is visible it receives all
  input and is drawn after everything else, including every overlay.

Out of scope: scrolling content (a ledger page longer than its page), a stack of
modals, new control types, and any game-specific look. See section 9.

## 2. How libcontrols is used today (constraints on the design)

These facts, read from the code, fix the shape of the design:

1. **Hosts are rebuilt per event and per frame.** `ControlHost<'a>` borrows its
   controls (`Box<dyn Control + 'a>` over `ControlHandle<'a, C>`).
   tinytrowel's `Clipboard::pointer` builds a fresh host for every pointer
   event and drops it; `Clipboard::build` draws controls without a host at
   all. Anything that must survive between events (which modal is open, its
   progress, focus inside it, a drag in progress) cannot live in the host or in
   `Modal`; it lives in an `Arc` state object, exactly as `ButtonState`,
   `SliderNumericState` and `PanelState` do, and as `ControlKey`/`DragGrab`
   were added for.
2. **Controls report through state and actions.** `ButtonState::take_click`
   is a take-once flag; `EventResponse::action` carries a `ControlAction`.
   Modal events follow the take-once pattern (`ModalState::take_events`)
   because some of them (`Opened`, `Closed`) are produced by time passing, not
   by an input event, so they cannot ride on an `EventResponse`.
3. **`ControlAction`, `Key` and `EventResponse` are exhaustive public types**
   with public fields; adding a variant or field can break a downstream
   exhaustive `match` or struct literal. The plan therefore adds no variants
   and no fields to existing types (section 8). tinytrowel only uses
   `if let Some(ControlAction::ValueChange { .. })`, but the rule holds anyway.
4. **Draw order is painter's order.** `DrawList` has no z value; what is pushed
   later is drawn on top. `DrawList::instances` is public and each
   `SdfInstance` (including a whole text run) carries a straight-alpha
   `color`. `push_clip`/`push_clip_end` and `push_translate`/
   `push_translate_end` exist; there is deliberately no `push_scale`.
5. **The library has no clock.** Nothing in libcontrols reads time;
   tinytrowel ages its toast in its own `tick(dt)`. Transitions are therefore
   advanced by the app (`ModalState::advance(dt)`) or driven by it outright
   (`ModalState::set_progress`).
6. **`ControlHost::deliver_keyboard` already treats `Key::Escape`** as "clear
   focus". With a modal visible, Escape dismisses the modal instead (when
   enabled).
7. **`Panel` draws its children's overlays inside its own `draw`**, because it
   calls `ControlHost::draw` on its child host. A modal must not do that if it
   clips its content, or tooltips would be clipped; it draws the two passes
   separately (step 4).

## 3. Concepts

- **Viewport**: the whole surface the host draws to, in the same pixel space as
  input events. The backdrop covers it.
- **Frame rect**: the area the modal visibly occupies (the parchment, the open
  book). A press outside it is a "tap outside". The app's `ModalFrame` may
  refine this to a non-rectangular shape (two book pages with a gutter).
- **Content rect**: the area inside the frame where libcontrols lays out and
  routes the modal's controls. The app positions the controls inside it in
  absolute coordinates, exactly as it does for `Panel` children.
- **Phase**: `Closed`, `Opening`, `Open`, `Closing`.
- **Progress**: `0.0` fully closed, `1.0` fully open. It rises during
  `Opening` and falls during `Closing`.
- **Capture**: in every phase except `Closed`, the modal layer takes every
  input event. Controls beneath receive nothing. Content controls receive
  input only in `Open`.

### 4.1 Phase, transition, reasons, events

```rust
/// Where a modal is in its life.
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq, Hash)]
pub enum ModalPhase {
    #[default]
    Closed,
    Opening,
    Open,
    Closing,
}

/// How progress moves between 0 and 1.
#[derive(Copy, Clone, Debug, PartialEq)]
pub enum ModalTransition {
    /// Progress jumps; open() and dismiss() finish their transition at once.
    Instant,
    /// Progress moves linearly with ModalState::advance(dt).
    /// A duration <= 0.0 behaves as Instant for that direction.
    Timed { open_secs: f32, close_secs: f32 },
    /// The app sets progress with ModalState::set_progress; advance() does nothing.
    Driven,
}

impl Default for ModalTransition {
    /// Timed { open_secs: 0.18, close_secs: 0.12 }.
    fn default() -> Self;
}

/// Why a modal began to close.
#[derive(Clone, Debug, PartialEq, Eq, Hash)]
pub enum DismissReason {
    /// A press and release both outside the frame.
    OutsideTap,
    /// Key::Escape, which shells also send for the platform back button.
    Escape,
    /// A content control registered with Modal::with_close_control was activated;
    /// carries its id ("close", "apply", "cancel", ...).
    Control(String),
    /// The app called ModalState::close() or dismiss(DismissReason::App).
    App,
    /// The app opened a different modal; this one closes first.
    Replaced,
}

/// Something the modal layer reports. Taken once with ModalState::take_events.
#[derive(Clone, Debug, PartialEq)]
pub enum ModalEvent {
    /// The opening transition finished; content now takes input.
    Opened { id: String },
    /// The modal began to close, and why.
    Dismissed { id: String, by: DismissReason },
    /// The closing transition finished; the modal is gone.
    /// Every Dismissed is followed by exactly one Closed with the same id and reason.
    Closed { id: String, by: DismissReason },
}
```

### 4.2 `ModalState` (persistent, app-owned)

```rust
/// Which modal is open and how far, shared between the app and every rebuild of the host.
#[derive(Debug, Default)]
pub struct ModalState {
    inner: Mutex<ModalInner>,
}

#[derive(Debug, Default)]
struct ModalInner {
    /// Default transition for open().
    default_transition: ModalTransition,
    /// The modal that is visible (Opening, Open or Closing), or None when Closed.
    current: Option<String>,
    phase: ModalPhase,
    /// 0.0 closed .. 1.0 open; always clamped to [0, 1].
    progress: f32,
    /// Transition of the current modal (from open_with or the default).
    transition: ModalTransition,
    /// Why the current modal is closing; Some only in Closing.
    reason: Option<DismissReason>,
    /// A modal asked for while another was visible; opened when that one reaches Closed.
    pending: Option<(String, ModalTransition)>,
    /// Events not yet taken, in the order they happened.
    events: Vec<ModalEvent>,
    /// Focus and drag inside the modal's content host, carried across rebuilds.
    focus: Option<ControlKey>,
    drag: Option<DragGrab>,
    /// Whether Modal::with_initial_focus has been applied since the last open().
    focus_seeded: bool,
    /// The button of a press that landed outside the frame while Open, awaiting its release.
    outside_press: Option<MouseButton>,
}
```

Public API (all `&self`; the `Mutex` gives interior mutability, matching
`PanelData`; `ModalState` is `Send + Sync`):

```rust
impl ModalState {
    pub fn new() -> Self;                                         // default transition
    pub fn with_transition(self, t: ModalTransition) -> Self;     // builder, sets default_transition

    pub fn open(&self, id: impl Into<String>);
    pub fn open_with(&self, id: impl Into<String>, t: ModalTransition);
    pub fn dismiss(&self, by: DismissReason);
    pub fn close(&self);                                          // dismiss(DismissReason::App)

    pub fn advance(&self, dt_secs: f32) -> bool;                  // true while a transition is still running
    pub fn set_progress(&self, progress: f32);                    // Driven (works in any mode)

    pub fn current(&self) -> Option<String>;
    pub fn is_current(&self, id: &str) -> bool;                   // current == Some(id)
    pub fn phase(&self) -> ModalPhase;
    pub fn progress(&self) -> f32;
    pub fn captures_input(&self) -> bool;                         // phase != Closed
    pub fn content_takes_input(&self) -> bool;                    // phase == Open
    pub fn is_animating(&self) -> bool;                           // Opening or Closing
    pub fn take_events(&self) -> Vec<ModalEvent>;                 // drains the queue
}
```

State machine (every row is a test in step 1):

| Phase now | Call / condition | Result |
|---|---|---|
| Closed | `open(id)` | `current = id`, `Opening`, `progress = 0`, focus/drag/`focus_seeded`/`outside_press` reset. With `Instant` (or `open_secs <= 0`): straight to `Open`, `progress = 1`, push `Opened`. |
| Opening | progress reaches `1.0` (via `advance` or `set_progress`) | `Open`, push `Opened { id }` |
| Opening or Open | `dismiss(by)` | `Closing`, `reason = by`, push `Dismissed { id, by }`; progress continues down from its current value. With `Instant` (or `close_secs <= 0`): straight to `Closed` as below, in the same call. |
| Closing | progress reaches `0.0` | `Closed`, push `Closed { id, by }`, `current = None`; then if `pending` is set, `open_with(pending)` |
| Opening or Open, same id | `open(id)` | no change |
| Opening or Open, other id | `open(other)` | `pending = other`, then `dismiss(Replaced)` |
| Closing, any id | `open(id)` | `pending = id` (the latest call wins); the close finishes first |
| Closed or Closing | `dismiss(_)` | no change (a second Escape while closing does nothing) |
| Any | `set_progress(p)` | `progress = clamp(p)`; the "reaches" rows above apply only in the matching phase (raising progress while `Closing` just moves it) |

`advance(dt)`: in `Opening` with `Timed`, `progress += dt / open_secs`; in
`Closing`, `progress -= dt / close_secs`; then the "reaches" rows apply.
`Instant` and `Driven` ignore it. Negative or non-finite `dt` is treated as 0.

### 4.3 `ModalView`, `ModalFrame`, `PanelFrame`

```rust
/// Everything a frame painter needs to draw one frame of the modal.
#[derive(Clone, Debug, PartialEq)]
pub struct ModalView<'s> {
    pub id: &'s str,
    pub phase: ModalPhase,
    pub progress: f32,
    pub viewport: Rect,
    pub frame: Rect,
    pub content: Rect,
}

/// The app-drawn look of a modal: its background, its animation, its shape.
pub trait ModalFrame {
    /// Draw the frame (parchment, open book, panel) under the content.
    fn draw_frame(&self, list: &mut DrawList, ctx: &DrawContext, view: &ModalView);

    /// Draw anything over the content (a page-curl shadow, a ribbon). Default: nothing.
    fn draw_over_content(&self, _list: &mut DrawList, _ctx: &DrawContext, _view: &ModalView) {}

    /// Whether a point is on the modal for tap-outside purposes. Default: view.frame.contains(pos).
    fn contains(&self, pos: [f32; 2], view: &ModalView) -> bool {
        view.frame.contains(pos)
    }
}

impl<F: ModalFrame + ?Sized> ModalFrame for &F { /* forwards */ }

/// The built-in frame: a rounded box with an optional border, in theme colours.
#[derive(Copy, Clone, Debug, PartialEq)]
pub struct PanelFrame {
    pub bg_color: Option<[f32; 4]>,      // None: ctx.theme.bg_color
    pub border_color: Option<[f32; 4]>,  // None: ctx.theme.accent_color
    pub border_thickness: f32,           // default 1.0; 0 draws no border
    pub corner_radius: Option<f32>,      // None: ctx.theme.corner_radius
}
```

`PanelFrame::draw_frame` pushes the same `RoundedBox`/`Outline` instances as
`Panel::draw`, with every colour's alpha multiplied by `view.progress`. A game
that wants a book implements `ModalFrame` on its own type and animates from
`view.progress` and `view.phase`; libcontrols never draws a look of its own
unless the app accepts `PanelFrame`.

### 4.4 Backdrop, reveal, dismiss rules

```rust
/// The dim drawn over everything beneath the modal.
#[derive(Copy, Clone, Debug, PartialEq)]
pub struct Backdrop {
    pub color: [f32; 4],          // default [0.0, 0.0, 0.0, 0.45]
    pub fade_with_progress: bool, // default true: alpha *= progress
}

/// How the content controls appear during a transition.
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
pub enum ContentReveal {
    /// Drawn only when Open (a book whose pages appear once it has opened).
    WhenOpen,
    /// Drawn in every visible phase with alpha multiplied by progress.
    #[default]
    Fade,
    /// Drawn unchanged in every visible phase; the frame painter does the rest.
    Always,
}

/// Which user actions dismiss the modal. Close controls are listed on Modal.
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
pub struct DismissOn {
    pub outside_tap: bool, // default true
    pub escape: bool,      // default true; also the platform back button
}
```

`ContentReveal::Fade` is implemented by remembering `start = list.instances.len()`
before drawing the content and, afterwards, multiplying
`list.instances[start..]`'s `color[3]` by `progress`. libmsdf has no group alpha
and no scale (section 2.4), so the library offers no scale or "pop" animation;
a slide is available to the frame painter through `push_translate`, and
content may use it only through `ContentReveal::Always`.

### 4.5 `Modal<'a>` (built with the host)

```rust
pub struct Modal<'a> {
    state: Arc<ModalState>,
    viewport: Rect,
    frame_rect: Rect,
    content_rect: Rect,
    frame: Box<dyn ModalFrame + 'a>,      // default Box::new(PanelFrame::default())
    backdrop: Option<Backdrop>,           // default Some(Backdrop::default())
    dismiss: DismissOn,                   // default DismissOn::default()
    close_controls: Vec<String>,          // ids that dismiss with DismissReason::Control(id)
    reveal: ContentReveal,                // default Fade
    clip_content: bool,                   // default true: push_clip(content) around the content's draw pass
    initial_focus: Option<ControlKey>,
    children: RefCell<ControlHost<'a>>,   // the content controls
}

impl<'a> Modal<'a> {
    pub fn new(state: Arc<ModalState>, viewport: Rect, frame: Rect, content: Rect) -> Self;
    /// frame centred in viewport at `size`; content = frame.pad(-padding).
    pub fn centered(state: Arc<ModalState>, viewport: Rect, size: [f32; 2], padding: f32) -> Self;

    pub fn with_frame<F: ModalFrame + 'a>(self, frame: F) -> Self;
    pub fn with_backdrop(self, backdrop: Option<Backdrop>) -> Self;
    pub fn with_dismiss(self, dismiss: DismissOn) -> Self;
    pub fn with_close_control(self, id: impl Into<String>) -> Self;   // may be called more than once
    pub fn with_reveal(self, reveal: ContentReveal) -> Self;
    pub fn with_clip_content(self, clip: bool) -> Self;
    pub fn with_initial_focus(self, key: ControlKey) -> Self;
    pub fn with_control<C: Control + 'a>(self, control: ControlHandle<'a, C>) -> Self;
    pub fn with_named_control<C: Control + 'a>(self, id: impl Into<String>, control: ControlHandle<'a, C>) -> Self;
    pub fn with_custom_control<H: Control + 'a>(self, control: H) -> Self;

    pub fn state(&self) -> &Arc<ModalState>;
    pub fn frame_rect(&self) -> Rect;
    pub fn content_rect(&self) -> Rect;
    /// None when the state is Closed.
    pub fn view(&self) -> Option<ModalView<'_>>;   // id borrowed from a String cached at build

    /// Route one event while the modal captures input (section 5).
    pub fn deliver_event(&self, event: InputEvent) -> EventResponse;
}

impl DrawControl for Modal<'_> {
    /// Backdrop, frame, content, content overlays, frame-over-content (section 6).
    /// Draws nothing when the state is Closed.
    fn draw(&self, list: &mut DrawList, ctx: &DrawContext);
}
```

`Modal::new` reads `state.current()` once and caches it (`id: String`) so
`view()` can lend a `&str`. The app builds the content for that id: it decides
what to build from `state.current()`, just as tinytrowel decides from its own
fields.

### 4.6 `ControlHost` additions

```rust
impl<'a> ControlHostBuilder<'a> {
    pub fn with_modal(self, modal: Modal<'a>) -> Self;     // new field: modal: Option<Modal<'a>>
}

impl<'a> ControlHost<'a> {
    pub fn set_modal(&mut self, modal: Option<Modal<'a>>);
    pub fn modal(&self) -> Option<&Modal<'a>>;
    /// A modal is present and its state is not Closed.
    pub fn captures_input(&self) -> bool;

    /// Pass 1: every hosted control's draw.
    pub fn draw_controls(&self, list: &mut DrawList, ctx: &DrawContext);
    /// Pass 2: every hosted control's draw_overlay; skipped while captures_input().
    pub fn draw_control_overlays(&self, list: &mut DrawList, ctx: &DrawContext);
    /// Pass 3: the modal layer, if any.
    pub fn draw_modal(&self, list: &mut DrawList, ctx: &DrawContext);
}
```

`impl DrawControl for ControlHost` becomes the three passes in order. With no
modal its output is byte-for-byte what 0.2.0 produced.

The split passes exist for apps that draw their own UI with `libmsdf` between
libcontrols' passes. Noble's Keep draws its tabletop first, then calls
`draw_modal` last into the same list (or renders a second list last), which is
how "above everything" holds for drawing that libcontrols does not own.

## 5. Input routing while a modal captures input

`ControlHost::deliver_mouse`, `deliver_keyboard`, `deliver_gesture` and
`deliver_modifiers` (and so `deliver_event`) each begin with:

1. Record the pointer (mouse) or modifiers as today.
2. If `!self.captures_input()`: continue exactly as 0.2.0.
3. Otherwise: set `self.active_drag = None`; on a mouse event call
   `set_hover(None)` on every base control (idempotent, so no "already
   cleared" flag is needed across rebuilds); on a modifiers event also call
   `set_modifiers` on every base control (the one exception, see question 4);
   then return `modal.deliver_event(event)`. Base controls get no
   `handle_mouse`, `handle_keyboard` or `handle_gesture`.

`Modal::deliver_event(event)`:

1. Load the content host's focus and drag from the state:
   `children.set_focused_key(state.focus)`, `children.set_active_drag(state.drag)`.
   If `!state.focus_seeded`, use `initial_focus` instead and set
   `focus_seeded = true`.
2. **Escape** (`KeyboardEvent` down with `Key::Escape`) in `Opening` or `Open`
   with `dismiss.escape`: `state.dismiss(Escape)`, return `consumed()`. With
   `dismiss.escape == false` it falls through to step 5 (the content host then
   clears its own focus, as 0.2.0 does).
3. **Not Open** (`Opening` or `Closing`): return `consumed()`. Nothing reaches
   the content.
4. **Tap outside** (mouse, `Open`, no content drag in progress):
   - `Down { pos, button }` with `!frame.contains(pos, view)`: set
     `outside_press = Some(button)`, return `consumed()`.
   - `Up { pos, button }` with `outside_press == Some(button)`: clear it; if
     `!frame.contains(pos, view)` and `dismiss.outside_tap`, `dismiss(OutsideTap)`.
     Return `consumed()`.
   - `Click { pos, .. }` outside with `outside_press == None` and
     `dismiss.outside_tap`: `dismiss(OutsideTap)`, return `consumed()`. (For
     shells that send only `Click`. A shell that sends `Down`, `Up` and `Click`
     dismisses on the `Up`; the `Click` then arrives in `Closing` and is
     swallowed by step 3.)
   - Any other mouse event outside the frame: `consumed()`.

   Requiring the press *and* the release outside means the release of the tap
   on the icon that opened the modal (which the app handled on `Down`) cannot
   close it, and a drag that starts on a slider and ends outside cannot either.
5. **Content**: `resp = children.deliver_event(event)`. If `resp.target_id` is
   in `close_controls` and `resp.action` is
   `Some(ControlAction::Activated { .. })`, call
   `dismiss(Control(id))`. Return `resp` unchanged.
6. Store `children.focused_key()` and `children.active_drag()` back into the
   state.

`consumed()` is `EventResponse { handled: true, target_index: None, target_id:
None, target_part: None, action: None, focused_index: None }`: handled, so the
app knows the event is spent, but naming no control.

While `captures_input()` is true, every `EventResponse` the host returns refers
to the modal's content host: `target_index` and `focused_index` are indices
among the modal's controls, and `target_id` is a content control's id. The app
checks `captures_input()` (or `ModalState::captures_input()`) before delivering,
and routes input to its own tabletop only when it is false.

Tab and BackTab cycle focus among the content controls only, because the
content host is separate from the base host; this is the modal's focus trap and
needs no extra code.

## 6. Drawing

`Modal::draw(list, ctx)`, when the state is not `Closed`:

1. `view = self.view()`.
2. Backdrop: if `Some(b)`, push one `SdfKind::Box` instance covering
   `viewport` with `color = b.color`, alpha multiplied by `progress` when
   `b.fade_with_progress`.
3. `frame.draw_frame(list, ctx, &view)`.
4. Content, unless `reveal == WhenOpen` and the phase is not `Open`:
   `start = list.instances.len()`; if `clip_content`,
   `list.push_clip(content.pos(), content.size())`;
   `children.draw_controls(list, ctx)`; `push_clip_end()`;
   `children.draw_control_overlays(list, ctx)` (outside the clip, so tooltips
   may leave the content rect; content controls should set
   `TooltipStyle::bounds` to the frame or viewport); if `reveal == Fade`,
   multiply `color[3]` of `list.instances[start..]` by `progress`.
5. `frame.draw_over_content(list, ctx, &view)`.

The host draws this after both of its own passes, so the modal is above every
base control and every base overlay. Base overlays are skipped entirely while
the modal captures input, so no stale tooltip under the modal is drawn.

## 7. How Noble's Keep uses it (informative)

```rust
// App state, once:
let modal = Arc::new(ModalState::new().with_transition(ModalTransition::Driven));

// The gear icon on the tabletop is the game's own libmsdf drawing and hit test:
if gear_tapped { modal.open("settings"); }

// Every frame:
book_anim.step(dt);                       // the game's own book-opening animation
modal.set_progress(book_anim.openness()); // 0..1
for ev in modal.take_events() { /* Closed{id:"settings",..} => persist settings */ }

// Input:
if modal.captures_input() { host.deliver_event(ev); } else { tabletop.input(ev); }

// Building the host (per event / per frame), content chosen by modal.current():
let host = ControlHost::builder()
    .with_modal(
        Modal::new(modal.clone(), viewport, book_rect, page_rect)
            .with_frame(BookFrame { .. })          // game's ModalFrame: cover, pages, curl
            .with_reveal(ContentReveal::WhenOpen)
            .with_close_control("close")
            .with_named_control("volume", volume.handle())
```

## 10. Open questions

1. **One modal or a stack?** This plan allows one, with `open(other)` closing
   the current one first (`Replaced`). A "Really quit?" confirmation inside the
   pause modal would be done by swapping that modal's content (same id, new
   controls), not by stacking. If the owner wants a confirm drawn *over* the
   settings book, a two-deep stack is the next plan.
2. **Platform back key.** Shells map Android back to `Key::Escape`, so
   `DismissReason::Escape` covers both. Adding `Key::Back` would let the two
   be told apart but adds a variant to an exhaustive public enum (a breaking
   change for any downstream exhaustive `match`). Is the distinction needed?
3. **Modal events in `ControlAction`?** They are delivered only through
   `ModalState::take_events`, because `Opened` and `Closed` come from time
   passing. Adding `ControlAction::Modal(ModalEvent)` as well would be a
   breaking change; worth it only with a move to `#[non_exhaustive]` in 0.3.
4. **Modifiers beneath a modal.** The plan forwards modifier changes to base
   controls even while capturing, because they are state, not actions, and
   withholding them leaves base controls with stale modifiers after the modal
   closes. Strictly, that is something "beneath" receiving input. Acceptable?
5. **Escape with a focused text field.** Escape dismisses even when an `Edit`
   in the modal has focus. Should the first Escape clear the field's focus and
   only a second one dismiss?
6. **Vetoing a dismissal.** There is no hook to refuse a dismissal (unsaved
   ledger edits). The app can turn off `outside_tap`/`escape` per modal and
   offer explicit close controls. Is a veto callback needed?
7. **Scrolling content.** A ledger page longer than the page needs a scroll
   container, which libcontrols does not have. Separate plan, or paginate in
   the game (turn the page)?
8. **Version and delivery.** `0.2.1` assumes additive changes are a patch
   bump. tinytrowel vendors a copy under `deps/libcontrols`; how will Noble's
   Keep consume it (git rev, path, or vendored copy)?
9. **Group alpha.** `ContentReveal::Fade` rewrites `instances[start..]`
   alpha after the fact. Instances whose colour comes from an animation bank
   entry (`anim != 0`) may not fade correctly. Should libmsdf grow a group
   alpha scope instead (a libmsdf change, outside this plan)?
10. **Default transition timing.** 0.18 s open, 0.12 s close is a guess for
    the built-in frame. Noble's Keep will mostly use `Driven`.

### A2. A modal stack in `ModalState`

The stack lives in the existing app-owned `Arc<ModalState>`; there is no
second type. Entries are ordered bottom to top.

1. **Layout** (replaces `ModalInner` in 4.2):

   ```rust
   pub const MAX_MODAL_DEPTH: usize = 4;

   struct ModalInner {
       default_transition: ModalTransition,
       entries: Vec<ModalEntry>,                 // bottom..top, at most MAX_MODAL_DEPTH
       pending: Vec<(String, ModalTransition)>,  // pushes waiting for a same-id entry to finish closing
       events: Vec<ModalEvent>,
   }

   struct ModalEntry {
       id: String,                               // unique among entries not Closing
       phase: ModalPhase,                        // Opening, Open or Closing; Closed entries are removed
       progress: f32,
       transition: ModalTransition,
       reason: Option<DismissReason>,            // Some only in Closing
       focus: Option<ControlKey>,
       drag: Option<DragGrab>,
       focus_seeded: bool,
       outside_press: Option<MouseButton>,
   }
   ```

   The **top** is the uppermost entry in `Opening` or `Open`; entries in
   `Closing` are on their way out and are never the top.

2. **API** (replaces the 4.2 API; all `&self`):

   ```rust
   impl ModalState {
       pub fn new() -> Self;
       pub fn with_transition(self, t: ModalTransition) -> Self;

       pub fn push(&self, id: impl Into<String>) -> bool;                       // false: duplicate id or stack full
       pub fn push_with(&self, id: impl Into<String>, t: ModalTransition) -> bool;
       pub fn open(&self, id: impl Into<String>) -> bool;                       // = push, kept for the body's examples
       pub fn replace_top(&self, id: impl Into<String>) -> bool;                // top closes (Replaced), id opens
       pub fn replace_top_with(&self, id: impl Into<String>, t: ModalTransition) -> bool;
       pub fn dismiss(&self, by: DismissReason);                                // closes the top only
       pub fn pop(&self);                                                       // dismiss(DismissReason::App)
       pub fn close(&self, id: &str);                                           // closes that entry, wherever it is (App)
       pub fn dismiss_all(&self, by: DismissReason);                            // every live entry, top first

       pub fn advance(&self, dt_secs: f32) -> bool;                             // every Timed entry; true while any animates
       pub fn set_progress(&self, id: &str, progress: f32);                     // Driven, per entry
       pub fn set_top_progress(&self, progress: f32);

       pub fn top(&self) -> Option<String>;
       pub fn depth(&self) -> usize;                                            // entries, Closing included
       pub fn contains(&self, id: &str) -> bool;                                // live (not Closing) entry
       pub fn phase(&self, id: &str) -> ModalPhase;                             // Closed if absent
       pub fn progress(&self, id: &str) -> f32;                                 // 0.0 if absent
       pub fn stack(&self) -> Vec<ModalEntryView>;                              // bottom..top snapshot
       pub fn captures_input(&self) -> bool;                                    // any entry at all
       pub fn top_takes_input(&self) -> bool;                                   // top exists and is Open
       pub fn is_animating(&self) -> bool;
       pub fn take_events(&self) -> Vec<ModalEvent>;
   }

   #[derive(Clone, Debug, PartialEq)]
   pub struct ModalEntryView { pub id: String, pub phase: ModalPhase, pub progress: f32, pub is_top: bool }
   ```

3. **Rules** (replace the 4.2 table; each row is a step 1 test):

   | Situation | Call / condition | Result |
   |---|---|---|
   | id not live, depth < 4 | `push(id)` | new entry on top in `Opening` (or `Open` + `Opened` if instant); entries below are untouched and emit nothing; returns true |
   | id already live | `push(id)` | no change, false |
   | depth == 4 (Closing entries count) | `push(id)` | no change, false |
   | id has an entry in `Closing` | `push(id)` | queued in `pending`, true; pushed on top when that entry emits `Closed` |
   | entry Opening | its progress reaches 1 | `Open`, `Opened { id }` |
   | top exists | `dismiss(by)` | top goes `Closing` with `by`, `Dismissed { id, by }`; the entry below becomes top again (it was never closed) |
   | no top | `dismiss(_)` / `pop()` | no change |
   | top exists, `id` not live | `replace_top(id)` | top: `Closing`, `Dismissed { by: Replaced }`; new entry pushed above it at once in `Opening`; both animate together. `Replaced` comes **only** from `replace_top`. Depth is checked as for `push` counting the outgoing entry |
   | no top | `replace_top(id)` | same as `push(id)` |
   | any | `dismiss_all(by)` | every live entry, top first, goes `Closing` with `by` and emits `Dismissed`; `pending` is cleared |
   | entry Closing | its progress reaches 0 | removed, `Closed { id, by }`; then any `pending` push for that id |

   Every event carries its entry's id. Every `Dismissed` is still followed by
   exactly one `Closed` for the same id.

4. **Transitions per entry.** Each entry keeps its own `ModalTransition` and
   progress. `advance(dt)` moves every `Timed` entry; `Driven` entries move
   only through `set_progress(id, p)` (or `set_top_progress`), so a game can
   drive the book's opening while a `Timed` confirm opens over it. An entry
   in `Closing` that is `Driven` stays visible until the app drives it to 0.

5. **Input** (replaces section 5's "the modal"): only the top's `Modal`
   receives input, by section 5's rules, applied to the top entry. Escape
   (`dismiss.escape`) gives `DismissReason::Escape`, Back (`dismiss.back`)
   gives `DismissReason::Back`; both close the top only. Tap outside is
   judged against the top's frame and closes the top only; a tap on a lower
   modal's frame is "outside" the top. When the top is `Opening`, or there is
   no top (everything is `Closing`), input is consumed and reaches nothing.
   Content controls of lower modals receive nothing and get `set_hover(None)`
   on each captured mouse event, as base controls do.
   `ControlHost::captures_input()` is true while any entry exists.

6. **`Modal` and the host** (replaces `Modal::new` in 4.5 and the 4.6
   methods):
   - `Modal::new(state, id: impl Into<String>, viewport, frame, content)`
     and `Modal::centered(state, id, viewport, size, padding)`: a modal is
     built for a named entry. A `Modal` whose id has no entry draws nothing
     and takes no input.
   - `ModalView` gains `depth: usize` (0 = bottom) and `is_top: bool`, so a
     frame painter can, for example, draw a lower book closed-but-visible.
   - `ControlHostBuilder::with_modal(modal)` may be called once per entry;
     `ControlHost::add_modal(modal)`, `modals(&self) -> &[Modal<'a>]` and
     `top_modal(&self) -> Option<&Modal<'a>>` replace `set_modal`/`modal`.
     The host orders the modals by the state's stack, not by the order they
     were added. If the app builds no `Modal` for the top id, input is still
     consumed.
   - The app builds one `Modal` per entry in `state.stack()`.

7. **Drawing** (replaces section 6's single pass): `draw_modal` draws every
   entry's `Modal` bottom to top, each with its own backdrop (so each new
   level dims everything under it, compounding), frame, content and
   frame-over-content. Lower modals are drawn because a confirm over the
   settings book should show the book beneath. Content **overlays**
   (tooltips) are drawn only for the top modal.
